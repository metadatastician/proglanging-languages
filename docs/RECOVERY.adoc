analysis, evaluation and benchmarking tool, cherry-pick what is relevant, merge
it". This page is the audit of that search: what was measured, what was found,
what could not be found, and what is now in `main` as a result.

Everything below is a measurement with a command behind it, not a recollection.

== Where the analysis tooling actually lives

The only real "language toolchain analysis, evaluation and benchmarking" code in
either account is in `metadatastician/cadastra`, under
`tools/estate-migration-toolkit/`, added by `91e46668` on 2026-07-16 and
unmoved since:

|===
| Upstream file | Lines | What it is | Disposition here

| `scripts/estate-scan.sh` | 455 | banned/allowed language sets, 8 anti-pattern detectors, classification table, CSV report | **ported** to `src/Languages.jl`, `src/Detect.jl`, `src/Classify.jl`, `src/Report.jl`
| `ci/language-gate.yml` | 311 | the same checks as a reusable workflow | **not adopted as-is** — see `FINDINGS.adoc` §F5 and §F8
| `scripts/rollout-language-gate.sh` | 266 | writes a caller into every repo | **not ported**; its target does not exist (§F8)
| `templates/.language-policy.toml` | 3.3 KB | per-repo policy file | **adopted**, with `[gate]` extensions (`nix_severity`, `strict`, `max_files`, `exclude`)
| `templates/language-gate-caller.yml` | 17 | caller stub | not adopted (§F8)
| `benches/template_bench.sh` | 180 | benchmark scaffold | superseded by `src/Bench.jl`
| `verification/benchmarks/README.adoc` | 3 | `= Benchmarks Unit` and nothing else | the gap this repo fills (§F6)
|===

The CSV schema is unchanged, deliberately:

....
source,name,primary_language,all_languages,classification,antipatterns,last_activity,stars_or_commits,forks,description
....

so any `estate-triage-report.csv` the estate already holds can be fed to
`proglanging report <file>` and re-counted without a re-scan.

== What is unrecoverable, and where a copy may still exist

The Julia console itself — the thing this repository was created for on
2026-09-20 — has no object anywhere in either account. Nothing in this PR can
recover it, because there is nothing to recover *from*.

The strongest surviving pointer to a local copy is the toolkit's own quick start,
which names the machine the analysis was run against:

....
./scripts/estate-scan.sh --github hyperpolymath metadatastician \
  --local ~/home/hyperpolymath/developer/hyper-repos ~/home/hyperpolymath/developer/meta-repos
....

and `standards#678` measured that 132 estate repositories track files their own
`.gitignore` hides — so a `Manifest.toml`, a `proglanging-report.csv`, or a
whole unreferenced directory can still be sitting in those trees. If a
`git status --ignored` in either directory turns up an untracked Julia project,
that is the original work and this scaffold should be rebased onto it rather
than the other way round.
