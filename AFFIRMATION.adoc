== What this is, and how it works

*What the project is.* A diagnostics console for a polyglot estate, written in
Julia with standard-library dependencies only. Given a repository, it reports
which languages the tree contains (by file extension), which of them the
estate's language policy bans, and which of eight architectural anti-patterns
it shows, with the files behind each anti-pattern. It then classifies the
repository (`DONE`, `CLEAN`, `MIGRATE`, `KILL`, ...) and gates it against the
repository's own `.language-policy.toml`. It also times its own walk, detect
and assess phases (`bench`) and can fail on a regression against a baseline
CSV. It is a port of the shell toolkit in `metadatastician/cadastra`
(`tools/estate-migration-toolkit/`).

*How this file stays trustworthy.*

. *Ground truth, not memory.* Every claim below comes from a command run in the
  session that wrote this file. Where a status document disagreed with a live
  run, the live run won and the document is named as stale in <<outstanding>>.
. *A frozen anchor.* <<verifiable-anchor>> names the exact commit, the branch,
  the UTC time, the working-tree delta and the toolchains. Move the SHA and

. *A real signature.* The file means something only once the owner lands it in

[#nuance]
=== The honest nuance you must not lose

* *"Evidence-backed classifications" holds for anti-patterns only.* Every
  anti-pattern finding names its files. A banned-*language* verdict does not:
  `analyze_directory` on `ZeroInflatedCounts.jl` returned `MIGRATE` with
  reason `banned languages detected: JavaScript` and an *empty* evidence
  dictionary, although the tree holds `scripts/check-action-pinning.js`.
  The `KILL` gate on `kill_repo` likewise prints no evidence block.
* *Language detection is by path, not content.* `src/Languages.jl` maps a
  file by extension (`EXT_MAP`), then by basename. `tools/selfcheck.sh` embeds
  Python heredocs, yet the self-gate's language list shows `Shell` and no
  `Python`, and `selfcheck.sh` prints `ok: no banned-language files outside
  test/fixtures`. The tool cannot see a language hidden inside another
  language's file.
* *"Standard-library-only" describes the Julia deps, not the runtime.* Local
  scans need `git` (non-git directories are skipped, and the HEAD date and
  commit count come from `git`). `scan --github` shells out to `gh` and uses
  the network (per `src/Scan.jl`; not run here). `tools/selfcheck.sh`
  needs `python3` and `ruby`, and Python is banned by the estate policy that
  this tool enforces.
* *`primary_language` is the first language the walk met, not the dominant
  one* (`src/Classify.jl` line 175: `files.langs[1]`). The self-scan reports
  `TOML` for this Julia repo, and both sample repos report `YAML`.
* *Without a policy file, every gate fails.* Every gate run on a repo with
  no `.language-policy.toml` (six runs) listed this failing reason:
  `no .language-policy.toml — defaults applied`. That is the documented
  intent, but a red gate on an unconfigured repo is not, by itself, a
  finding about its code.
* *"Scan timing" means the separate `bench` command.* No `scan` run above
  printed a timing. `bench` times walk, detect and assess over one
  repository; it does not time an estate scan.
* *Bench numbers are noisy at `--reps 3`.* The walk median was 7.30 ms, then
  3.37 ms, then 1.25 ms in three runs on the same machine within 11 minutes.
  A 10% regression tolerance at that sample size can flap.
* *The 1.11 CI leg was not run here.* CI's matrix is `1.10` and `1.11`; this
  session ran 1.10.10 and 1.12.6.
* The console prints the banner `PROGLANGING SCAN COMPLETE` even on a scan it
  then declares `INCOMPLETE` (rc=3). The exit code and the closing line are
  right; the banner is not. `gate .` prints an empty `repo:` field, because
  the basename of `.` is empty.
